# 审核检查 Agent - 业务规则

## 适用范围

XF质量 → 审核检查 Agent MVP 是 XF质量 下的新业务工作流，与 FMEA生成 Agent 并列。

MVP 只审核用户粘贴的纯文本内容，并生成结构化审核发现。不处理 docx/pdf 文件上传。

## 输入

工作流接收以下字段：

- `audit_type`：审核类型，只能是 `quality_issue`、`pfmea`、`audit_record`、`general`
- `content`：用户粘贴的待审核文本
- `focus`：可选，审核重点
- `background`：可选，补充背景

## 输出

输出结构化审核发现。每条 finding 必须包含：

- `issue`：发现问题
- `category`：问题类型
- `risk_level`：风险等级，只能是 `低`、`中`、`高`、`需人工确认`
- `risk_explanation`：风险说明
- `evidence_from_input`：来自用户输入文本的依据
- `basis`：来自 FMEA手册 / VDA6.4 检索材料的规范依据
- `recommendation`：整改建议
- `manual_check_required`：是否需要人工确认

## 通用审核规则

1. 不得编造标准条款、条款编号、页码或文件要求。
2. 检索材料依据不足时，必须写 `需人工确认`。
3. 每条整改建议必须针对具体问题和输入依据，不能泛泛而谈。
4. 审核发现必须区分“用户输入依据”和“规范依据”。
5. 审核发现必须清晰可读，不能依赖隐藏推理才能理解。
6. 如果用户输入内容不完整，必须指出缺失信息，并设置 `manual_check_required=true`。
7. Agent 可以使用通用质量知识提示风险，但不能把通用知识伪装成标准依据。

## 按审核类型的检查重点

### `pfmea`

审核 PFMEA 内容时，重点检查：

- 失效链是否一致：功能/要求 -> 失效模式 -> 失效后果 -> 失效原因
- 失效原因是否具体，是否只是重复描述失效模式
- 预防控制是否针对失效原因
- 探测控制是否能够发现失效模式、失效后果或失效原因
- 建议措施是否针对高风险原因或控制缺口形成闭环
- 建议措施是否说明改什么、由哪个过程或责任方执行、如何验证有效性

### `quality_issue`

审核质量问题描述时，重点检查：

- 问题定义和影响范围是否清楚
- 原因分析是否有足够深度和证据
- 纠正措施是否针对根本原因
- 预防措施是否能够降低复发风险
- 整改验证是否有客观证据
- 是否混淆遏制、纠正、纠正措施和预防措施

### `audit_record`

审核审核记录时，重点检查：

- 不符合项证据是否具体、可追溯
- 要求或规范依据是否清楚；依据不足时是否标注 `需人工确认`
- 整改措施是否针对不符合项
- 是否明确责任人或责任部门
- 是否明确完成期限
- 是否包含验证闭环和验收证据

### `general`

审核一般文本时，重点检查：

- 证据是否充分
- 规范依据是否充分
- 风险是否说明清楚
- 责任和闭环是否明确
- 文本是否需要人工复核后才能正式使用

## 引用与依据

- `basis` 必须优先使用检索到的 FMEA手册 / VDA6.4 材料。
- 如果没有检索材料支持某条发现，`basis` 必须写 `需人工确认`。
- 不得编造精确条款、页码、章节或标准要求。
- 如果检索材料只能提供宽泛原则，不能直接支撑结论，应在 `basis` 中写明为宽泛依据，并设置 `manual_check_required=true`。

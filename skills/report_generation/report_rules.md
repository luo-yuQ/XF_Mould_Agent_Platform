# 报告生成规则

## 报告类型

MVP 只支持：

- `quality_issue_report`：质量问题分析报告。

## 章节规则

### 问题背景

- 使用用户提供的 `extra_background`、已选择 FMEA 输入、已选择 Audit 输入或已选择运行记录摘要。
- 背景不足时，必须明确写 `背景信息不足，需人工确认`。

### 分析对象与范围

- 从已选择运行记录中概括产品、工序、失效现象、审核对象和分析边界。
- 不得推断无关的产品线、工序、客户、地点或批次。

### 参考依据

- 可引用已选择 FMEA 运行记录、已选择 Audit 运行记录、可选 RAG 参考依据和用户输入。
- 不得编造标准条款、页码、章节编号或文件要求。
- 如果 RAG 依据缺失或不足，必须写 `未检索到充分标准依据，需人工确认`。

### FMEA分析摘要

- 只能摘要已有 FMEA 行。
- 不得新增失效模式、原因、控制措施、S/O/D/AP 评分、RPN 或建议措施。
- 如果缺少 `fmea_run_id`，或对应运行记录没有可用内容，必须写 `未提供相关结果，需人工确认`。

### 审核发现摘要

- 只能摘要已有审核发现。
- 不得新增审核发现、风险等级、证据、依据或建议。
- 如果缺少 `audit_run_id`，或对应运行记录没有可用内容，必须写 `未提供相关结果，需人工确认`。

### 风险判断

- 风险判断必须基于 FMEA 风险信号、审核发现、用户背景和可选 RAG 参考依据。
- 结论必须与前文证据对应。
- 依据不足时，必须将判断标为 `需人工确认`。

### 改进措施建议

- 每条建议至少必须能追溯到一个来源：FMEA、Audit、用户输入或 RAG。
- 不得提出与已选择运行记录无关的措施。
- 不得把通用质量知识包装成正式标准依据。

### 需人工确认事项

- 必须包含来源内容缺失、标准依据不足、风险判断不确定和未验证假设。
- FMEA 或 Audit 缺失时，必须列入对应人工确认项。

### 结论

- 只总结前文已有证据支持的结论。
- 不得在结论中引入新事实。

## 输出规则

1. 只输出 Markdown。
2. 使用 `report_template.md` 中的固定章节顺序。
3. 每个结构化 `ReportSection` 都必须保留来源追溯信息。
4. 不生成 Word 或 PDF。
5. 不解析或处理上传文件。
6. 不对报告产物做向量化。
7. 不修改 FMEA 或 Audit 源内容。

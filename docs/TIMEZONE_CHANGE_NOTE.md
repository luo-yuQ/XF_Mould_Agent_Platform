# 时间与时区改动说明

## 改动原因

系统此前将时间按 UTC 写入数据库，但数据库字段没有记录时区，接口返回的时间文本也没有明确标记 UTC。浏览器收到这种时间后，会把它当作用户电脑所在时区的本地时间处理。

因此，中国用户看到的创建时间可能比实际北京时间慢八小时。该问题并不是系统使用了美国时间，而是 UTC 时间在传输过程中丢失了时区信息。

## 改动方式

系统仍然统一使用 UTC 保存时间，不直接把数据库时间改成北京时间。这样可以避免服务器部署地区、用户所在地和夏令时变化造成混乱。

数据库中的用户、会话、消息、会话摘要、FMEA、Audit 和 Report 时间字段已改为带时区的时间类型。历史记录原本就是按 UTC 生成，因此迁移时将历史值明确解释为 UTC，不对时刻本身增加或减少小时数。

后端新建或更新时间时，统一生成带 UTC 时区信息的时间。接口返回时间时会携带明确的 UTC 标识。

前端继续使用浏览器本地时区显示时间。中国时区的浏览器会自动显示为北京时间，其他地区的用户会看到各自所在地时间。

## 改动后的时间含义

- 数据库存储：统一 UTC，并带时区信息。
- 接口传输：明确标记 UTC。
- 页面显示：按浏览器所在时区转换。
- 中国用户：正常显示北京时间。

## 历史数据处理

已有时间值不会被当作北京时间重新转换。迁移只补充“这些值属于 UTC”的信息，因此不会造成历史记录整体偏移八小时。

## 影响范围

本次改动只统一时间的保存、传输和显示语义，不修改 FMEA、Audit、Report、聊天、RAG 或其他业务流程。
